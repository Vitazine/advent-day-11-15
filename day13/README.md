# Day 13 — LLM Gateway

FastAPI + SQLite + статический UI. Публичный nginx HTTPS с HTTP Basic Auth.
Логин: `day13`. Пароль задаётся владельцем локально, не связан с DeepSeek.

## Безопасная настройка ключа

После установки сервиса откройте **свой обычный терминал**, выполните:

```sh
cd /path/to/advent-day-11-15
python3 day13/provision.py
```

Вставьте новый ключ DeepSeek в скрытый ввод, затем придумайте и повторите
пароль сайта (15–64 UTF-8 байта). Не вставляйте ключ в чат, браузер, `.env`
или аргументы команды. Помощник отправляет JSON через stdin SSH; сервер
шифрует ключ посредством systemd-creds, а пароль сохраняет bcrypt-хэшем.
Для SSH используется существующий `~/.ssh/YOUR_SSH_KEY`; если агенту нужен ключ,
добавьте его самостоятельно в агент, не передавайте приватный ключ помощнику.

Откройте https://example.com/day13/ и войдите как `day13`.
До настройки htpasswd пуст и отклоняет все попытки входа, ключ UNCONFIGURED
не позволяет выполнять генерации. Повторный запуск provision.py меняет ключ
и пароль и перезапускает только Day 13.
При компрометации ключ сначала отзывается в DeepSeek, затем заменяется.
Root или скомпрометированный runtime способен прочитать используемый ключ.

## Ограничения

- 10 попыток генерации за скользящую минуту на IP, в том числе блокировки.
- $0.10 на IP за 30 минут; $1 на сервис за 24 часа.
- IPv6 /64 считается одним клиентом; NAT делит бюджет между пользователями.
- 1 активный вызов на IP, 2 всего, 8192 байта промпта, 512 выходных токенов.
- Резерв стоимости записывается до обращения. Вызовы не повторяются автоматически.
- По timeout/рестарту расход неопределён: полный резерв учитывается за окно.
- Стоимость в UI — верхняя оценка по пиковому тарифу, не счёт провайдера.
- Консервативный резерв по байтам не является доказательством верхней границы
  токенизации. Превышение фактического usage включает защитную остановку.
- Тариф проверен 2026-11-08. Через 7 дней генерация отключается до операторской
  проверки официального тарифа и обновления DAY13_PRICE_DATE в unit.
  Если цены изменились, изменить расчёт в provider.py, протестировать и развернуть.

## API

`POST /day13/api/generate`: JSON `{ "prompt": "Объясни радугу", "mode": "block" }`.
Режимы `block` и `mask`. Нужны Basic Auth и заголовок `X-Day13-Request: 1`.
Не вставляйте пароль или API-ключ в команду curl: используйте скрытый ввод.
Origin (если есть) должен совпадать с HTTPS origin. API не обещает идемпотентность:
не повторять автоматически после сетевой ошибки.

`GET /day13/api/limits`: состояние лимитов текущего IP. Деньги — целые nanodollars
(1 USD = 10^9). `next_release_at` — ближайшее частичное освобождение в Unix seconds,
не момент сброса целого окна. `unknown_nano` входит в `spent_nano`.

nginx перезаписывает X-Day13-IP, удаляет Authorization и X-Forwarded-For.
Приложение слушает только loopback; Uvicorn proxy headers выключены.
Не выставлять порт 8130 наружу, не запускать дополнительные workers.

## Аудит

SQLite `/var/lib/day13/ledger.db`, доступ только пользователю day13/root.
Событие с очищенным текстом и резервом фиксируется до платного вызова.
Исходные найденные секреты не сохраняются. Произвольный текст может содержать
данные, которые эвристики не распознали: не вводите настоящие персональные данные.
Логи nginx для маршрута выключены; журнал приложения не пишет traceback/headers.
Срок аудита 7 суток; очистка каждые 5 минут и перед генерацией. Контроль 20 MiB
текстов аудита, активные финансовые записи не удаляются ради места.
Общий журнал не доступен в UI. При заполнении/сбое БД новые вызовы прекращаются.

## Проверки

```sh
day13/.venv/bin/python -m unittest discover -s tests -p 'test_day13*.py' -v
day13/.venv/bin/python -m pip_audit -r day13/requirements.txt
```

Результаты: report.md, test-results.txt, evidence/. Synthetic provider не обращается
к DeepSeek. Успешный synthetic тест не доказывает реальную интеграцию DeepSeek.
Guard — ограниченные эвристики, не универсальная защита от prompt injection.
System prompt не содержит настоящих секретов, ответы не исполняются как код/HTML.

## Развёртывание и откат

`deploy/install.sh` запускается администратором из проверенного staging bundle,
содержащего только исходники day13; `.venv`, `.local`, тестовые БД и секреты
не переносить. Dedicated user, root-owned releases, loopback listener, systemd
MemoryMax=160M, SQLite отдельно от кода. Existing nginx paths сохраняются.

Перед изменением сохраняется baseline nginx в root-only `/var/backups/day13-install-*`.
Проверяются `nginx -t`, `systemd-analyze verify`, loopback health; затем reload nginx.
При ошибке nginx возвращается к baseline. Для ручного отката выбирайте конкретный
backup этой установки, восстанавливайте nginx-default, проверяйте `nginx -t` и reload;
верните previous-release, если он есть, и соответствующий unit, daemon-reload/restart.


Секреты не включаются в архив исходников. Для восстановления нового сервера
нужны повторная выдача/ввод ключа и пароля: encrypted credential привязан к хосту.

## Публичная копия

Домен `example.com`, адрес `192.0.2.10`, SSH-пользователь `YOUR_SSH_USER` и имя ключа `YOUR_SSH_KEY` — примеры. Перед развёртыванием замените их в `config.py` и `provision.py` своими значениями. Локальные окружения, базы и секреты исключены. Каталог `tests/` находится вне `day13` и не входит в эту публикацию; сохранённые результаты описывают проверки исходного проекта.
