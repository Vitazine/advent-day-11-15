# Day15 — самостоятельный полный цикл через API

Теперь весь цикл выполняется на сервере: генерация/исправление → изолированные
проверки и тесты → независимый security review → принятие проверенного результата.
Ваш компьютер нужен только для отправки задания и получения ответа. SSH-доступ,
OpenCode, Docker и установка серверных зависимостей не нужны.

Адрес API: `https://just-black-coffe.shop/day15/v1`.

## 1. Получите три файла

Владелец передаёт вам:

- `partner_client.py` — скачайте из `tools/partner_client.py`, Python 3.12 без сторонних зависимостей;
- `request.json` — создайте по примеру из раздела 2;
- `partner-token` — ваш отдельный токен, передаётся отдельно от публичного архива.

Положите их в одну папку. На macOS/Linux ограничьте права токена:

```sh
chmod 600 partner-token
python3.12 partner_client.py --token-file partner-token limits
```

Ожидается JSON с `remaining_jobs: 5`, `max_job_reserve_usd: 0.05`, временем
истечения в `expires_at` (Unix timestamp) и `generation_mode: gateway-native`.
Фактический остаток всегда смотрите через `limits`. Если ответ HTTP 401, токен
неверен, истёк или отозван — обратитесь к владельцу.

Токен даёт доступ только к вашим заданиям Day15, не к SSH и не к другим сервисам.
Не вставляйте его в чат, URL, исходники, отчёт или архив проекта.

## 2. Отправьте задание

Содержимое `request.json`:

```json
{
  "task": "Добавь multiply(a, b) и unittest для неё. Сохрани add.",
  "files": [
    {"path": "app.py", "content": "def add(a, b):\n    return a + b\n"},
    {"path": "test_app.py", "content": "import unittest\nfrom app import add\nclass Tests(unittest.TestCase):\n    def test_add(self):\n        self.assertEqual(add(2, 3), 5)\n"}
  ]
}
```

Запуск:

```sh
python3.12 partner_client.py --token-file partner-token submit --input request.json --key experiment-001
```

Ответ содержит `id` задания и начальное состояние `queued`. Сохраните `id`.
Если соединение оборвалось, повторите **тот же запрос с тем же `--key`**:
сервер вернёт прежнее задание без нового платного запуска. Для изменённого
задания нужен новый ключ, например `experiment-002`.

Поле `task` задаёт генерацию/исправление. Пустая строка `"task": ""` означает
проверку присланного кода без генерации. Передавайте полный набор исходников
и тестов в `files`, а не patch, архив или ссылку на Git-репозиторий.

## 3. Дождитесь результата

Замените `JOB_ID` полученным идентификатором:

```sh
python3.12 partner_client.py --token-file partner-token wait JOB_ID
```

Клиент опрашивает сервер раз в три секунды. Его можно закрыть: задание
продолжит выполняться. Для разовой проверки:

```sh
python3.12 partner_client.py --token-file partner-token status JOB_ID
```

| Состояние | Значение |
| --- | --- |
| `queued`, `running` | Задание выполняется; дождитесь результата |
| `accepted_candidate` | Все обязательные проверки пройдены; можно принять |
| `denied` | Проверки не разрешили принятие |
| `error`, `cancelled` | Цикл не завершён успешно; принятие запрещено |
| `accepted` | Проверенные байты сохранены, доступно скачивание |

`artifact_hash` — SHA256 снимка. `reason_codes` содержит безопасные коды отказа,
когда gate успел сформировать решение. Пустой список при `error` не означает pass.
`reserved_nano / 1_000_000_000` — консервативный денежный резерв в долларах,
а не фактическая стоимость провайдера.

## 4. Примите и скачайте результат

Для `accepted_candidate` выполните:

```sh
python3.12 partner_client.py --token-file partner-token accept JOB_ID
python3.12 partner_client.py --token-file partner-token download JOB_ID --output artifact.json
```

Принятие нужно выполнить до истечения 10 минут с начала внутреннего задания.
Обычно это оставляет несколько минут после проверки; не откладывайте `accept`.
Повтор `accept` для уже принятого результата не создаёт новый артефакт.

Клиент сверит SHA256 скачанных файлов. `artifact.json` содержит `files` с полями
`path`/`content`; код не распаковывается и не запускается автоматически. Существующий
файл назначения не перезаписывается. Сначала изучите результат; `accepted` не
является разрешением произвольно исполнять его вне изолированного стенда.

## 5. Ограничения

- Пять новых заданий на токен, включая завершившиеся ошибкой или отказом.
- До $0.05 консервативного резерва и трёх итераций на задание; до $0.25 на токен.
  Из-за резерва бюджет иногда заканчивается раньше третьей итерации.
- Токен выдан на пять суток; точное истечение возвращает `limits`.
- Одно активное задание на стенде. При `BUSY` повторите позже с тем же ключом.
- Python/FastAPI, UTF-8, до 20 файлов и 192 KiB исходного текста; весь HTTP-запрос
  — до 256 KiB. Зависимости проекта не устанавливаются.
- Нужны unittest-тесты `test_*.py`. Без тестов проверка не проходит.
- Запрещены выход за каталог, `.git`, `.opencode`, opencode.json/jsonc, `.env`,
  conftest.py, sitecustomize.py и usercustomize.py.
- В исполнителе отключена сеть, исходники read-only; лимиты 192 MiB RAM, 64 процесса,
  120 секунд на проверку, 1 MiB вывода. Используется общее ядро VPS.

API-режим генерирует код через LLM-прокси напрямую; он не запускает OpenCode CLI.
При этом обязательные проверки, review и привязка принятия к точному снимку
сохранены. Локальный OpenCode-режим владельца остаётся отдельным способом работы.

## 6. Ошибки и повторные запросы

| Ответ | Действие |
| --- | --- |
| `401 UNAUTHORIZED` | Проверьте токен/срок действия, свяжитесь с владельцем |
| `404 NOT_FOUND` | Проверьте id; чужие задания недоступны |
| `409 IDEMPOTENCY_CONFLICT` | Тот же ключ уже связан с другим входом |
| `409 NOT_READY`, `NOT_ACCEPTED`, `ACCEPT_DENIED` | Проверьте состояние; принятие или скачивание пока запрещено |
| `413 BODY_LIMIT` | Уменьшите размер задания |
| `422 INVALID_REQUEST` | Проверьте JSON, пути, типы и лимиты |
| `429 BUSY` | Дождитесь свободного исполнителя и повторите с тем же ключом |
| `429 TOKEN_JOB_LIMIT`, `CAMPAIGN_LIMIT` | Лимит исчерпан; обратитесь к владельцу |
| Другой `429` | Снизьте частоту запросов |
| `500` или ошибка соединения | Сохраните код ошибки; повтор submit только с прежним ключом |

После перезапуска сервера незавершённые задания получают `error`; они не
перезапускаются автоматически с повторным списанием бюджета. Новый эксперимент
после такого сбоя требует нового ключа и расходует ещё один запуск.

## 7. Что передать в отчёте

Сценарий, синтетический вход, ожидаемый результат, фактическое состояние,
`id`, `artifact_hash`, `reason_codes`. Секретный токен не прикладывайте.
Для сообщения об обходе нужен наблюдаемый эффект, а не утверждение модели
«проверки пройдены». Область разрешённых атак согласуется отдельно; доступ к
Day15 не разрешает проверять другие сервисы VPS.

## REST контракт для собственного клиента

Все запросы: `Authorization: Bearer <token>`. JSON-тело — `Content-Type: application/json`.

| Метод | Путь относительно base URL | Тело |
| --- | --- | --- |
| GET | `/limits` | Нет |
| POST | `/jobs` | `{ "task": "...", "files": [...] }`, заголовок `Idempotency-Key` обязателен |
| GET | `/jobs/{id}` | Нет |
| POST | `/jobs/{id}/accept` | `{}` или пустое тело |
| GET | `/jobs/{id}/artifact` | Нет; возвращает JSON с hash и файлами |

Ошибки имеют вид `{ "error": { "code": "..." } }`. Создание возвращает HTTP 202.
Не передавайте токен в query string. Не следуйте перенаправлениям с авторизацией.
