# Advent Challenge — Day 11–15

Учебные эксперименты по защите LLM и полный цикл проверки генерируемого Python-кода.

| Каталог | Содержимое |
| --- | --- |
| `day11` | Прямые prompt injection и сравнение защит |
| `day12` | Косвенные инструкции в материалах и ответы инструментов |
| `day13` | Базовый LLM gateway |
| `day14-v2` | Прокси для OpenCode, ограниченный DLP, независимый security review |
| `day15-defense` | Снимки исходников, изолированные проверки, обязательный gate, партнёрский API |

## Запуск партнёром

[Инструкция](day15-defense/PARTNER_START.md) · [Клиент](day15-defense/tools/partner_client.py)

API: `https://just-black-coffe.shop/day15/v1`. Нужен отдельный токен, который владелец
передаёт приватно. В репозитории токенов нет. Python-клиент использует стандартную
библиотеку; партнёру не нужны SSH, Docker или OpenCode.

Серверный цикл: генерация через LLM gateway → неизменяемый снимок → Ruff/Bandit/
AST/unittest в ограниченном Linux-окружении → независимый review → явное принятие
точных проверенных байтов. Серверный API не запускает OpenCode CLI; отдельный
локальный OpenCode-режим сохранён. Автоматической публикации сгенерированного кода нет.

## Проверки исходников

Python 3.12. Из корня каждого компонента создайте venv и установите его зависимости:

```sh
cd day14-v2
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

```sh
cd day15-defense
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-api.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m redteam.run --mode deterministic
```

При подготовке публикации проверяются обе публичные копии. Unit-тесты не требуют
реальных ключей; relay-тесту нужен временный localhost socket. Живые платные
эксперименты запускаются отдельно только с разрешённым доступом.

## Состав публикации

Публикуются исходники, синтетические fixtures, зависимости, примеры службы и
инструкции. Локальные токены, верификаторы токенов, рабочие БД, credentials,
журналы, приватные результаты и эксплуатационные архивы не включены.
История ранее опубликованных Day11–13 сохранена.

Административный SSH-хост в публичной версии заменён на `executor.example.com`.
Это исходники для изучения и настройки своего экземпляра, а не готовый доступ
к VPS владельца. Fingerprint публичной копии может отличаться от установленного;
самостоятельный deployment требует согласованной версии API и worker.

Общее ядро VPS слабее отдельной VM. Эвристические DLP/сканеры и LLM-review не
гарантируют обнаружение всех уязвимостей. Доступ к API не разрешает атаковать
другие сервисы. Реальные секреты и персональные данные не использовать в fixtures.
